# FERPEK Lens 0.4.3

FERPEK Lens 0.4.3 introduces the self-update infrastructure used to manage future compatible Lens releases from the WebUI.

This release also improves update visibility, recovery handling and Agent enrollment for deployments using custom ports or reverse proxies.

## Highlights

- Added FERPEK Lens update checks in **Settings → Updates**.
- Added update checks for installed official FERPEK packs.
- Added the host-side FERPEK Lens update helper.
- Added controlled asynchronous update jobs with progress reporting.
- Added transactional deployment updates with automatic rollback.
- Added interrupted-update detection and recovery.
- Added persisted updater state and recovery context.
- Added updater protocol compatibility checks.
- Added release artifact validation before deployment.
- Added secure staging and deployment backups.
- Added updater housekeeping for old backup and staging data.
- Added post-update health and version verification.
- Added update progress and recovery controls to the WebUI.
- Update-check results now remain visible after leaving and returning to Settings.

## Agent enrollment

Agent enrollment now uses the public FERPEK Lens URL instead of assuming that the Server API is available on port `8000`.

The WebUI now proxies the files required by Agent installation:

- `/install-agent.sh`
- `/agent.py`
- `/pack-engine.py`

This allows the enrollment command generated by the WebUI to work with:

- custom WebUI ports;
- reverse proxies;
- deployments exposed through HTTPS.

For example, when Lens is opened at:

    https://lens.example.com

the generated enrollment command uses the same public origin instead of exposing an internal Docker or Server API port.

## Upgrade from 0.4.2

FERPEK Lens 0.4.2 predates the host-side update helper introduced in 0.4.3.

Existing 0.4.2 installations therefore require a one-time bootstrap before in-app Lens updates become available.

Run the bootstrap on the machine hosting FERPEK Lens:

    curl -fsSL https://raw.githubusercontent.com/ferpekdev/ferpek-lens/2e56a0b/deploy/bootstrap-0.4.3.sh | sudo sh

The bootstrap:

1. verifies that the existing installation is FERPEK Lens 0.4.2;
2. identifies and preserves the existing FERPEK Lens data volume;
3. creates a backup of the deployment configuration;
4. downloads the 0.4.3 deployment and updater artifacts;
5. pulls the official 0.4.3 container images;
6. installs the host-side update helper;
7. starts FERPEK Lens 0.4.3;
8. verifies the Server, WebUI, updater socket and running version;
9. verifies that the same persistent data volume is still mounted.

If the deployment step fails after changes begin, the bootstrap attempts to restore the previous 0.4.2 deployment configuration.

The bootstrap does not run operating-system upgrades and does not intentionally remove the FERPEK Lens data volume.

!!! warning

    Do not use `docker compose down -v` during the upgrade. The `-v` option removes the persistent Docker volume used by FERPEK Lens.

## After upgrading

Starting with FERPEK Lens 0.4.3, future compatible Lens releases can be managed from:

**Settings → Updates**

The updater performs release validation, staging, deployment backup, health checks and rollback handling as part of the update workflow.

## Backup recommendation

The bootstrap preserves the existing FERPEK Lens data volume and creates a backup of the deployment configuration.

As with any software upgrade, keeping an independent current backup of important FERPEK Lens data before upgrading is recommended.
