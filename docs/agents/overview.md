# Agents

The FERPEK Agent runs directly on monitored hosts and connects them to the central FERPEK Lens server.

Its role is to discover available sources, synchronize pack configuration, process logs and report structured information back to FERPEK Lens.

## What the agent does

The FERPEK Agent is responsible for:

- enrolling the host with the FERPEK Lens server;
- reporting basic host information;
- discovering available log sources;
- discovering services that may be supported by packs;
- synchronizing packs assigned to the host;
- loading and processing pack rules;
- collecting configured log sources;
- reporting Relevant activity;
- reporting Findings and associated event data;
- maintaining durable local state when the server is temporarily unavailable.

## Enrollment

A new agent is enrolled using a temporary token generated by the FERPEK Lens server.

The enrollment token is:

- temporary;
- single-use;
- removed from the local agent configuration after successful enrollment.

After enrollment, the agent receives its own credentials and uses them for future communication with the server.

The enrollment token is only required during the initial registration process.

## Host identity

After enrollment, FERPEK Lens maintains an identity for the host.

The agent reports information such as:

- hostname;
- operating system;
- operating system version;
- machine type;
- agent version;
- last connection time.

This information is displayed in the FERPEK Lens web interface.

## Source discovery

The agent discovers log sources that are available on the host.

Depending on the operating system and installed services, these may include:

- authentication logs;
- general system logs;
- kernel events;
- scheduled task activity;
- service errors;
- mail logs;
- web server logs;
- journald sources;
- additional sources introduced by packs.

Discovery does not automatically mean that every source is actively monitored or forwarded to the server.

Monitoring behaviour depends on the host configuration and active packs.

## Pack discovery

Packs can define discovery rules that allow the agent to determine whether a service or log source is available on a host.

FERPEK Lens uses this information to present packs that may be relevant to that host.

A pack may be:

- detected automatically;
- configured manually;
- waiting for required configuration;
- unavailable on the host.

Discovery and activation are separate operations.

A discovered pack is not automatically activated.

## Pack synchronization

Pack activation is controlled by the FERPEK Lens server.

When a pack is activated for a host, the agent synchronizes the required pack files and configuration.

When pack configuration changes, the agent automatically updates its local state.

This allows the server to manage pack assignments centrally while the actual log processing remains on the monitored host.

## Local processing

Pack rules are processed locally by the FERPEK Agent.

This allows service-specific interpretation to happen close to the original log source.

Depending on the pack, the agent can produce structured information such as:

- Relevant activity;
- Findings;
- supporting event information.

The exact behaviour depends on the rules provided by the active packs.

## Log collection

The agent can collect logs from supported source types.

Which sources are active depends on:

- source discovery;
- host configuration;
- enabled packs;
- Log Explorer settings.

FERPEK Lens distinguishes between monitoring a source and forwarding events for inspection.

A source can therefore contribute to detections without necessarily sending every matching event to the central interface.

## Durable delivery

The agent maintains durable local state for information that has not yet been successfully delivered to the FERPEK Lens server.

This helps reduce data loss during temporary network or server interruptions.

When connectivity is restored, pending information can be delivered to the server.

## Connectivity

The agent must be able to reach the FERPEK Lens server.

The server address is configured during installation and stored locally by the agent.

Network routing, firewalls and security policy must allow communication between the monitored host and the FERPEK Lens server.

With the current default deployment, the FERPEK Lens API is exposed on port:

    8000

## Existing installations

The installer detects whether FERPEK Agent credentials already exist on the host.

When an enrolled installation is detected, the installer refuses to perform another enrollment.

This prevents an existing agent identity from being replaced accidentally.

Upgrade, repair and reinstall workflows are still being developed.

## Platform support

The FERPEK Agent is currently focused on Debian-based Linux systems.

Additional operating systems and Linux distributions will be documented when their installation and runtime paths are implemented and tested.

## Debian-based Linux

The following details apply to the currently supported Debian-based Linux agent.

### Service

The FERPEK Agent runs as a systemd service:

    ferpek-agent.service

Check whether the service is active:

    systemctl is-active ferpek-agent.service

View the complete service state:

    systemctl status ferpek-agent.service

Restart the agent:

    systemctl restart ferpek-agent.service

### Agent logs

The agent writes operational messages to the system journal.

View recent messages:

    journalctl -u ferpek-agent.service -n 50 --no-pager

Follow the logs in real time:

    journalctl -u ferpek-agent.service -f

Typical messages may include:

    Connected to FERPEK Server
    Reported discovery for 4 pack(s)
    Pack synchronized: openssh
    FERPEK Lens reloaded 1 pack(s)

The exact output depends on the host configuration and active packs.

### Credentials

Agent credentials are stored in:

    /etc/ferpek/agent.json

The file is restricted to root.

The agent environment is stored in:

    /etc/ferpek/environment

After successful enrollment, the environment file should contain the FERPEK Lens server address without the temporary enrollment token.

### Pack storage

Synchronized pack data is stored below:

    /var/lib/ferpek/packs

The agent manages this directory automatically.

### Privileges

The current Linux agent runs as root.

This is required because infrastructure logs, journald sources and service files are not always accessible to an unprivileged process.

The privilege model may differ on future supported platforms.
