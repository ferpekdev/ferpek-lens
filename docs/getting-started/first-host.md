# Add your first host

FERPEK Lens monitors infrastructure through the FERPEK Agent.

The agent runs directly on the host, discovers available log sources and reports information back to the FERPEK Lens server.

## Open the Hosts page

In the FERPEK Lens web interface, open:

**Hosts**

Then select:

**Add host**

FERPEK Lens will generate a temporary enrollment token and display the installation command for that host.

The token is single-use and expires automatically.

## Run the installation command

Copy the command shown by FERPEK Lens and run it on the Linux host you want to monitor.

The current automatic installer is intended for Debian-based Linux systems.

The command must be executed by root or by a user with sudo privileges.

A generated command will look similar to:

    curl -fsSL http://FERPEK_SERVER:8000/install-agent.sh | sudo bash -s -- --server http://FERPEK_SERVER:8000 --token ENROLLMENT_TOKEN

Do not reuse an old command or enrollment token.

Always use the current command generated by the FERPEK Lens web interface.

## What the installer does

The installer performs the following steps:

1. Checks that the required installation parameters are present.
2. Installs the required Python dependencies.
3. Creates the FERPEK Agent directories.
4. Downloads the FERPEK Agent from the FERPEK Lens server.
5. Creates the local agent configuration.
6. Installs and enables the `ferpek-agent.service` systemd service.
7. Starts the agent and verifies that enrollment completes.

A successful installation ends with:

    FERPEK Agent installed and enrolled successfully.

## Enrollment

During the first startup, the agent uses the temporary enrollment token to register the host with the FERPEK Lens server.

After successful enrollment:

- the server creates an identity for the agent;
- the host receives its own agent credentials;
- the credentials are stored locally;
- the temporary enrollment token is removed from the agent configuration.

The enrollment token is not intended to remain on the host after enrollment.

## Agent credentials

The agent stores its credentials in:

    /etc/ferpek/agent.json

The credentials file is restricted to root.

The agent configuration is stored in:

    /etc/ferpek/environment

After successful enrollment, the environment file should contain the FERPEK Lens server address without the temporary enrollment token.

## Systemd service

The FERPEK Agent runs as:

    ferpek-agent.service

Check the current state with:

    systemctl status ferpek-agent.service

For a shorter status check:

    systemctl is-active ferpek-agent.service

A correctly running agent should report:

    active

## View agent logs

Agent logs are available through journald:

    journalctl -u ferpek-agent.service

To view recent log entries:

    journalctl -u ferpek-agent.service -n 50 --no-pager

A successful initial connection will include messages similar to:

    Enrollment successful.
    Connected to FERPEK Server

## Host connection in FERPEK Lens

The Add host window automatically waits for the enrollment to complete.

When the agent connects successfully, FERPEK Lens displays:

**Host connected**

The host then appears in the Hosts page.

FERPEK Lens can display information such as:

- hostname;
- operating system;
- machine type;
- agent version;
- connection status.

## Discovery

After connecting, the agent reports available log sources and performs discovery for compatible packs.

Discovery allows FERPEK Lens to determine which monitoring packs may be useful for that host.

A discovered pack is not automatically activated.

You decide which packs should be enabled for each host.

## Enable packs

Open the host in FERPEK Lens and go to the **Packs** section.

Available packs may appear with states such as:

- Active
- Available
- Disabled
- Unavailable
- Needs configuration

Activate the packs that correspond to services you want FERPEK Lens to monitor.

After activation, the agent synchronizes the pack configuration automatically.

## Verify pack synchronization

The FERPEK Agent logs pack synchronization activity.

You may see messages similar to:

    Pack synchronized: openssh
    FERPEK Lens reloaded 1 pack(s)

The exact output depends on which packs are enabled for the host.

## Existing installations

The installer will refuse to perform a new installation when the host already contains enrolled FERPEK Agent credentials.

If you see:

    FERPEK Agent is already enrolled on this host.

the existing installation should be reviewed instead of running the enrollment command again.

Upgrade, repair and reinstall workflows are still being developed.

## Troubleshooting

If the host does not connect:

1. Check that `ferpek-agent.service` is running.
2. Check the agent logs with `journalctl`.
3. Confirm that the host can reach the FERPEK Lens server.
4. Confirm that port `8000` is reachable from the host.
5. Generate a new enrollment token if the previous token expired or was already used.

Do not manually reuse expired or previously consumed enrollment tokens.
